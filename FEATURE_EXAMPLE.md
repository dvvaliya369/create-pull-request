# Feature: Default PR Title and Body from Commit Message

## Overview
This feature implements GitHub Issue #4111, which allows the action to automatically default the PR title and body to the commit's subject and body when creating a pull request with a single commit.

## How It Works

When the following conditions are met:
1. The pull request branch contains exactly **one commit**
2. The `title` input is at its default value (`'Changes by create-pull-request action'`)
3. The `body` input is at its default value (`'Automated changes by [create-pull-request](https://github.com/peter-evans/create-pull-request) GitHub action'`)

The action will automatically:
- Use the commit's **subject** as the PR title
- Use the commit's **body** as the PR body (if the body is not empty)

This behavior mimics GitHub's web interface when creating a PR from a single commit.

## Example Usage

### Before (Issue #4111)
Users had to duplicate the commit message in the workflow:

```yaml
- uses: peter-evans/create-pull-request@v7
  with:
    commit-message: |
      Update AGP sources to the latest

      _Auto-generated by `dump-sources` Github workflow._
    title: Update AGP sources to the latest
    body: _Auto-generated by `dump-sources` Github workflow._
    branch: actions/dump-sources
    delete-branch: true
```

### After (With This Feature)
Users can now omit `title` and `body` for single-commit PRs:

```yaml
- uses: peter-evans/create-pull-request@v7
  with:
    commit-message: |
      Update AGP sources to the latest

      _Auto-generated by `dump-sources` Github workflow._
    branch: actions/dump-sources
    delete-branch: true
```

The PR will automatically have:
- **Title**: `Update AGP sources to the latest`
- **Body**: `_Auto-generated by \`dump-sources\` Github workflow._`

## Backward Compatibility

This feature is **fully backward compatible**:
- If you explicitly set `title` or `body`, those values will be used (no change in behavior)
- If you have multiple commits, the default values will be used (no change in behavior)
- Only single-commit PRs with default title/body values will use the new behavior

## Edge Cases Handled

1. **Empty commit body**: If the commit has no body, the default PR body is used
2. **Whitespace-only body**: Treated as empty, default PR body is used
3. **Multi-line commit body**: Preserved as-is in the PR body
4. **Multiple commits**: Default title and body are used (no auto-defaulting)
5. **Custom title/body**: User-provided values are always respected

## Testing

The feature includes comprehensive unit tests covering:
- Single commit with subject and body
- Single commit with empty body
- Single commit with whitespace-only body
- Multi-line commit bodies
- Multiple commits (should not default)
- Custom title/body (should not override)

All tests pass successfully, and the feature maintains backward compatibility with existing workflows.
